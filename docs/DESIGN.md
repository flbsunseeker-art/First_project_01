# StockPilot Design

## 0. 文档信息

- 产品名称：StockPilot
- 当前阶段：MVP
- 关联文档：[PRD.md](./PRD.md)
- 设计目标：先建立清晰、一致、可实现的产品体验基线，后续在功能稳定后再做更精细的视觉升级。

## 1. 设计定位

StockPilot 的界面应像一个个人股票资产驾驶舱：安静、清楚、可信，有一点科技感，但不喧宾夺主。

核心体验关键词：

- **简约大气**：页面层级清楚，信息密度高但不压迫。
- **暗色金融感**：以深蓝黑为主背景，用冷色光效表达数据氛围。
- **数据可信**：收益、成本、汇率、行情状态必须一眼可判断。
- **多端适配**：Web 端优先，同时结构天然适配移动端。
- **先功能后精修**：第一期不追求复杂动效和强视觉装饰，避免影响核算与开发节奏。

## 2. 参考方向

用户提供的三张参考图可以提炼为三个可借鉴点：

1. **Portfolio Tracker**：清晰的 KPI 卡片、资产分布、持仓表格和深色卡片布局。
2. **科技驾驶舱**：深色背景、蓝色发光曲线、模块化面板和轻微空间感。
3. **数据分析 Dashboard**：紧凑的信息网格、图表组合、筛选条和趋势分析区域。

StockPilot 不直接复制这些界面，而是采用「暗色卡片 + 冷色数据图表 + 红绿收益语义」的轻量版本。

## 3. 视觉方向

### 3.1 主题名称

**Night Ledger**

含义：一个夜间模式的个人投资总账，强调冷静、秩序和可解释的数据。

### 3.2 视觉原则

- 背景使用深蓝黑，不使用纯黑，降低视觉疲劳。
- 卡片使用比背景更亮的蓝灰色，形成清楚的层级。
- 重要数字使用大字号和等宽数字样式，保证财务数据易读。
- 红色固定表示盈利、上涨、正收益。
- 绿色固定表示亏损、下跌、负收益。
- 蓝色用于中性操作、数据状态、趋势线和科技感点缀。
- 黄色/橙色只用于警告、数据缺失和风险提示。

## 4. 信息架构

MVP 页面结构：

```text
StockPilot
├── 总览
│   ├── 核心 KPI
│   ├── 数据状态
│   ├── 总市值趋势
│   └── 每日收益概览
├── 持仓
│   ├── 当前持仓表
│   ├── 行业分布
│   └── 市场分布
├── 交易
│   ├── 新增交易
│   ├── 交易流水
│   └── 导入导出
├── 收益分析
│   ├── 收益日历
│   ├── 每日收益柱状图
│   └── 累计收益 / 总市值曲线
└── 设置与数据
    ├── 证券信息
    ├── 行业编辑
    ├── 数据同步状态
    └── 数据库备份
```

第一期目标前端使用 Next.js / React 实现响应式 Web。桌面端优先采用侧边导航或顶部导航，移动端优先采用底部 Tab。

## 5. 页面设计

### 5.1 总览页

目标：用户打开应用后，3 秒内知道当前股票资产是否健康。

首屏模块：

- 顶部品牌区：`StockPilot`、一句短说明、最新估值日期。
- KPI 卡片：
  - 总持仓成本
  - 股票总市值
  - 累计盈亏
  - 累计收益率
  - 今日盈亏
  - 今日收益率
- 数据状态条：
  - 行情是否完整
  - 汇率是否完整
  - 历史估值是否补齐
  - 当前数据是否为临时盘中数据
- 关键图表：
  - 股票总市值趋势
  - 每日盈亏柱状图

设计要求：

- KPI 使用横向卡片网格，Web 端 4 到 6 列，移动端 2 列或单列。
- 盈亏数字必须带正负号。
- 累计盈亏下方展示累计收益率。
- 今日盈亏下方展示今日收益率。

### 5.2 持仓页

目标：让用户看清每只股票的贡献、风险和仓位。

模块：

- 持仓明细表
- 行业分布图
- 市场分布图
- 可选筛选：市场、行业、盈亏状态

持仓表字段：

- 市场
- 名称
- 代码
- 行业
- 股数
- 平均成本
- 最新价
- 成本(CNY)
- 市值(CNY)
- 仓位%
- 盈亏(CNY)
- 盈亏率%
- 今日涨跌%

设计要求：

- 收益为红，亏损为绿。
- 金额列右对齐，使用等宽数字。
- 行业字段可编辑，但视觉上应像基础信息，不像交易字段。
- 表格在移动端改为卡片列表，避免横向滚动过长。

### 5.3 交易页

目标：低摩擦记录买卖，同时保留复盘素材。

模块：

- 新增交易表单
- 交易流水表
- 编辑 / 删除交易入口
- CSV 导入导出

设计要求：

- 买入和卖出用明确的标签区分。
- 交易理由分类使用固定选项：
  - 行业趋势判断
  - 个股基本面
  - 价格 / 估值判断
  - 仓位 / 情绪管理
- 修改历史交易后，需要有明显提示：后续快照会重算。

### 5.4 收益分析页

目标：帮助用户理解收益随时间的变化。

模块：

- 收益日历
- 每日收益柱状图
- 总市值趋势线
- 累计收益趋势线

收益日历设计：

- 月视图优先。
- 盈利日期红色浅底，亏损日期绿色浅底。
- 当前日期使用描边或高亮角标。
- 无数据日期显示 `—`。
- 异常日期显示警告样式。
- 点击日期后展示当日明细：总市值、当日买入、当日卖出、每日盈亏、数据状态。

趋势图设计：

- 总市值使用蓝色折线。
- 累计收益使用红/绿语义色或中性蓝色，取决于正负区间。
- 每日盈亏使用柱状图，红柱盈利、绿柱亏损。

### 5.5 设置与数据页

目标：让用户知道数据从哪里来、是否可信、如何备份。

模块：

- 证券列表与行业编辑
- 行情同步状态
- 汇率同步状态
- 历史补算状态
- 数据库备份
- HTML 报告导出

设计要求：

- 数据异常不要藏在角落，应作为可见状态展示。
- 错误信息要说明是行情缺失、汇率缺失还是估值失败。
- 数据库备份入口要清楚，但不需要高频曝光。

## 6. 组件规范

### 6.1 KPI 卡片

内容结构：

```text
指标名称
主数值
副指标 / 收益率 / 状态说明
```

样式：

- 背景：深蓝灰卡片。
- 边框：低透明蓝色描边。
- 正收益：红色数值。
- 负收益：绿色数值。
- 异常状态：黄色提示。

### 6.2 图表卡片

图表统一放在卡片中。

要求：

- 标题在左上角。
- 时间范围或筛选在右上角。
- 坐标轴文字弱化。
- 网格线使用低透明度。
- 图例少而清楚。

### 6.3 表格

要求：

- 表头固定使用浅灰蓝。
- 行 hover 使用轻微蓝色背景。
- 金额、股数、百分比右对齐。
- 名称、代码、行业左对齐。
- 收益列统一红绿语义。

### 6.4 状态提示

状态类型：

- 正常：蓝色 / 青色
- 警告：黄色 / 橙色
- 错误：红色
- 未知：灰色

数据缺失时优先解释原因，不展示伪准确结果。

## 7. 设计 Token

第一期可先在 Next.js 全局 CSS、组件样式和 HTML 报告中使用以下 token。

```css
:root {
  --bg-page: #07111f;
  --bg-panel: #0f2239;
  --bg-panel-soft: #122945;
  --border-soft: #1e3a5f;
  --text-primary: #f8fafc;
  --text-secondary: #94a3b8;
  --text-muted: #64748b;
  --accent-blue: #38bdf8;
  --accent-cyan: #22d3ee;
  --profit-red: #fb7185;
  --loss-green: #34d399;
  --warning: #fbbf24;
  --danger: #f87171;
}
```

字体建议：

- 中文界面：`PingFang SC`, `Noto Sans SC`, `Microsoft YaHei`, sans-serif。
- 数字与金额：优先使用 tabular numbers；正式 Web 版本可考虑 `DIN`, `Barlow Condensed` 或类似金融数据字体。

## 8. 响应式设计

断点建议：

- Desktop：`>= 1024px`
- Tablet：`768px - 1023px`
- Mobile：`< 768px`

Desktop：

- 使用宽屏 Dashboard。
- KPI 4 到 6 列。
- 图表 2 列布局。
- 表格完整展示。

Tablet：

- KPI 2 到 3 列。
- 图表 1 到 2 列。
- 表格保留横向滚动或减少非关键列。

Mobile：

- 顶部只保留品牌、估值日期和数据状态。
- KPI 改为 2 列或纵向卡片。
- 持仓表改为卡片列表。
- 收益日历保持月视图，但单元格简化为日期 + 金额。
- 导航优先使用底部 Tab：
  - 总览
  - 持仓
  - 交易
  - 分析
  - 设置

## 9. 可访问性与可读性

- 红绿颜色必须配合正负号，不只依赖颜色表达。
- 关键金额保留千分位和两位小数。
- 异常状态使用文字说明，不能只使用图标。
- 卡片和表格对比度需保证暗色模式下可读。
- 移动端点击区域不小于 44px。

## 10. 第一阶段实施优先级

P0：

- 统一深色主题与设计 token。
- 总览 KPI 信息完整。
- 持仓表红绿收益语义一致。
- 收益日历与趋势图可读。
- 数据状态清楚可见。

P1：

- 移动端布局简化。
- 持仓卡片化展示。
- 图表卡片统一样式。
- HTML 报告视觉与应用一致。

P2：

- 更精细的品牌区。
- 轻量动效。
- 更高级的筛选交互。
- 更完整的移动端导航。

## 11. 暂不投入

第一期暂不投入：

- 大规模自定义动效；
- 复杂 3D 科技背景；
- 多套主题切换；
- 完整移动 App 视觉重做；
- 高保真原型制作；
- 品牌 Logo 深度设计。

原因：当前阶段优先保证核算正确、功能完整、页面清楚。视觉只需要建立统一方向，避免后续实现发散。

## 12. 验收标准

- 页面整体为统一暗色主题。
- 总览、持仓、交易、收益分析、设置页面视觉语言一致。
- Web 端宽屏下信息密度足够，不显空散。
- 移动端可阅读、可操作，不依赖宽表格完成核心任务。
- 盈利/上涨统一红色，亏损/下跌统一绿色。
- 成本、市值、盈亏、收益率在视觉层级上清楚区分。
- 行业分布和市场分布与持仓表使用一致的总市值口径。
- 数据异常状态可以被用户明确感知。
- HTML 报告与应用保持同一套颜色和信息层级。
